## Виявлені проблеми та рекомендації

### 🔴 Критичні проблеми:

1. **Валідація унікальності постачальників**
   - Проблема: Можна створити кілька постачальників з однаковими іменами
   - Тест: `test_T3_duplicate_name`
   - Рекомендація:
     ```python
     # У SupplierService.create()
     existing = self.dao.get_by_name(name)
     if existing:
         raise ValueError("Supplier with this name already exists")
     ```

2. **Валідація негативних значень qty**
   - Проблема: Можна створити компонент з qty = -10
   - Тести: `test_T4_negative_qty`, `test_T5_update_negative_qty`
   - Рекомендація:
     ```python
     from pydantic import Field

     class ComponentCreate(BaseModel):
         qty: int = Field(default=0, ge=0)  # ge = greater or equal
     ```

3. **Валідація enum для статусу замовлень**
   - Проблема: Можна передати будь-який рядок як status
   - Тест: `test_T5_invalid_status`
   - Рекомендація:
     ```python
     from enum import Enum

     class OrderStatus(str, Enum):
         PENDING = "pending"
         COMPLETED = "completed"
         CANCELLED = "cancelled"

     class OrderCreate(BaseModel):
         status: OrderStatus = OrderStatus.PENDING
     ```

### ⚠️ Середні проблеми:

4. **Перевірка залежностей перед видаленням**
   - Проблема: Можна видалити постачальника, який має активні замовлення
   - Тест: `test_T3_delete_with_orders`
   - Рекомендація:
     ```python
     # У SupplierService.delete()
     orders = self.order_dao.get_by_supplier_id(supplier_id)
     if orders:
         raise ValueError("Cannot delete supplier with active orders")
     ```

5. **Коректні HTTP коди помилок**
   - Проблема: Порожній рядок повертає 400 замість 422
   - Використовуйте стандартні Pydantic validators для правильних кодів
